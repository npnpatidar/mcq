# Round-2 review — accessibility, strings & localisation (cross-cutting)

**Branch:** `feature/review-round-2` @ `fbc8e15` (= main, release 0.0.61). **Read-only** — no product/test/gradle/docs code changed.
**Scope:** `res/values/strings*.xml` vs `res/values-hi/strings*.xml`; hardcoded literals in `main/`; content descriptions, semantics/`stateDescription`, live regions/`LocalAnnouncer`, touch targets, colour-only signalling, theme contrast, RTL, text scaling; language picker (`AppLanguage`).
**Method:** old reports 17-E and 19-G treated as **claims**; scripting diffed 1,291 EN / 1,271 HI resource names, placeholders, plural quantities, apostrophes, whitespace and duplicates; literals traced to call sites; guards read in full. Platform claims verified against official docs: [Compose semantics](https://developer.android.com/develop/ui/compose/semantics) (`stateDescription` "reads out the state"; `mergeDescendants=true` → single leaf; live regions "shouldn't be used on content that updates frequently, such as countdown timers"), [string resources](https://developer.android.com/guide/topics/resources/string-resource) (escape apostrophes; plurals need `one`+`other`), [announceForAccessibility](https://developer.android.com/reference/android/view/View#announceForAccessibility(java.lang.CharSequence)), [app languages](https://developer.android.com/guide/topics/resources/app-languages).

## Verdict

The **resource system itself is now in full EN↔HI parity**: every one of the 1,271 translatable names exists in both locales, with zero placeholder/plural/apostrophe/duplicate defects. All 20 EN-only names are exactly the `translatable="false"` brand/format set (verified set equality) — correct, not missing translations. The old "no localisation / 25 unused resources / non-plural counts / no announcer / 117 invisible format calls" claims are genuinely fixed.

The residual failure is a **different failure mode**: ~70 user-facing strings never became resources at all — they sit in enum/data holders, formatter functions and parameter-passed literals. Both the locale files and every guard are structurally blind to them, so a Hindi user gets a translated screen with an English dialog/state/warning inside it. Two genuine a11y defects remain (the merged formula WebView hides the question; selectable controls still speak no state), plus timer-announcement gaps.

## Findings

**A1 — Medium (i18n, root cause) — ~70 user-facing literals live outside the resource system; parity tooling cannot see them.** *Evidence* (all verified at source): `ExportFormat.kt:11-60` 8 formats × `title`+`description` = **16** literals (rendered raw at Library `778,810`, Bookmarks `326,328`, Browse `869`); `domain/ReviewFilters.kt:12-18` **7** filter constants (rendered raw at `ResultsScreen.kt:377-390`; only SLOW special-cased to a resource at `:384`); `domain/Models.kt:204-207` **3** `Difficulty` labels (Editor `:914,926`); `domain/TestTiming.kt:17-21` **3** warning messages (`TestViewModel.kt:771`); `StudyScreen.kt:841-845,861,927-939,508` **9** (4 option states, 4 grade buttons, 1 enum-name grade label); `BackupDataSection.kt:119,135,138` **3** (2 messages + chooser title — `R.string.export_logs` already exists in both locales); `StatsAggregator.kt:1906-1914` **20** histogram labels + 9 `Locale.ENGLISH` date patterns (`:1331,1871,2593,2594`, `ExamStats.kt:474,476`, `HeatmapChart.kt:61-62`, `CardInfoSheet.kt:44`); `LibraryPaperCard.kt:180-182` summary; Browse/Search `(N questions)`, 3 chips, `(blank text)`, 3 scope labels (`05` report B5); import fallbacks `Category`/`Passage`/cloze (`09` I6). *Why missed:* the 0.0.57/0.0.59/0.0.60 `final_*` + Hindi sweeps resource-ified strings *inside* files; `StringResourceUsageTest` only checks resources. *Fix:* promote each holder field to `@StringRes`, resolve with `stringResource`/`pluralStringResource` at call sites; keep stored tokens/mime/extensions unchanged.

**A2 — Medium (a11y + i18n) — option states and grade labels are hardcoded English and are read aloud.** `StudyScreen.kt:841-845` builds `optionState` from `"Correct answer"/"Selected, wrong answer"/"Selected"/"Not selected"` and `:861` assigns it to `stateDescription`; `:927,930,936,939` pass `"Again"/"Hard"/"Good"/"Easy"`; `:508` derives the result label from `ReviewGrade.name`. `R.string.grade_again…grade_easy` and `correct_answer` already exist in both locales, but are not used here. The official [state-description example](https://developer.android.com/develop/ui/compose/semantics) resolves each state string with `stringResource` precisely because TalkBack reads it out — under Hindi, TalkBack reads English. *Why missed:* the `Role.Checkbox`/`stateDescription` fix (db612e0) fixed the *channel*, not the copy; `noHardcodedUserFacingLiteralInComposeTextOrFeedback` matches only `Text("…")` and `contentDescription = "…"`, not a value later assigned to `stateDescription`. *Fix:* `@StringRes` on option/grade states, resolve in both locales; derive grade label from the same resources. (Consolidates round-2 02-S2.)

**A3 — Medium (i18n) — chart dates and axis labels stay English under Hindi.** `StatsAggregator.kt:1331,1871,2593-2594` + `ExamStats.kt:474,476` + `HeatmapChart.kt:61-62` + `CardInfoSheet.kt:44` use `DateTimeFormatter.ofPattern(..., Locale.ENGLISH)`; `:1906-1914` holds literal `"1–2w"/"2–4m"/"0–5s"`-style bucket labels. A Hindi user sees translated headings with English months and tokens. Numeric formatting via `Locale.ENGLISH` (e.g. `ChartKit.kt:294`) is deliberate and **excluded**. *Why missed:* locale tests cover resource names, not `DateTimeFormatter` patterns in domain/Canvas. *Fix:* pass the selected locale into formatters; resolve bucket labels via resources. (Consolidates round-2 06-ST2.)

**A4 — High (a11y) — formula-bearing question content is one generic TalkBack node with the question text hidden.** `ContentElements.kt:49-51` routes *any* element list containing `MathElement` into `MixedContentView`; `:469,542` merges the whole WebView into a single leaf with `contentDescription = R.string.a11y_rich_content`, whose value is only "Rendered question content with formulas" (`strings.xml:1263`). Per [Compose semantics](https://developer.android.com/develop/ui/compose/semantics), `mergeDescendants = true` makes descendants one leaf, so no question text, table cell or math is exposed; the plain-text path at `:53-56` is never taken. The formula *editor* WebView was fixed to speak its current LaTeX (`MathLiveEditor.kt:138`), but the *content* WebView was given a label instead of content. *Why missed:* db612e0 answered "WebViews unlabelled" with a label; the guard `richContentPreviewWebViewHasASpokenLabel` asserts that exact label. *Fix:* expose a real accessible text fallback (`stateDescription` with plaintext/annotation or a non-merging labelled node), or let TalkBack traverse the WebView's own tree ([accessible WebView](https://developer.android.com/guide/webapps/accessible-webview)). (Consolidates 08-E3.)

**A5 — Medium (a11y) — selectable/toggle controls still announce no state and no label.** `TestSessionScreen.kt:389-416` flag/bookmark are plain `IconButton`s with static `contentDescription` (`flag_question`, `bookmark_question`) — state is glyph/tint only, unlike the clock which got `stateDescription` at `:1060`; answer-review rows `:969-1000` are `.clickable{}.padding(vertical=6.dp)` with no `heightIn(48.dp)` and no "go to question N" label; `BrowseScreen.kt:1136,1161` checkbox and ✓/○ correctness markers unlabelled; `LibraryDrawer.kt:329-338` / `LibraryDialogs.kt:223-263` checkbox/radio rows unlabelled. Docs: state description "reads out the state" ([semantics](https://developer.android.com/develop/ui/compose/semantics)). `UiAccessibilityTest.touchTargetsAreNotSmallerThanTheMinimum` only scans `IconButton`/`IconToggleButton` modifiers, so raw `.clickable` rows slip through. *Fix:* `IconToggleButton` + localized `stateDescription`, `selectable`/`Role` + `onClickLabel`, `heightIn(min=48.dp)`. (Consolidates 03-T2/T3, 05-B6, 01-L9.)

**A6 — Medium (a11y + i18n) — timer warnings are English and unannounced; countdown urgency is colour-only.** `TestTiming.kt:17-21` → `TestViewModel.kt:771-773` stores an English sentence in `timeWarning`; the card at `TestSessionScreen.kt:477-502` is not announced (announcer covers only `loadError`/`saveError` at `:152-157`). The top-bar countdown `:361-381` is two unlinked nodes with colour-only 60 s urgency. Official guidance says live regions should not be used on frequently updating content like countdown timers — announce the *threshold once*, not each tick ([semantics](https://developer.android.com/develop/ui/compose/semantics)); status messages likewise need a text/announcement channel ([WCAG 4.1.3](https://www.w3.org/WAI/WCAG21/Understanding/status-messages.html)). *Fix:* `%1$d`-arg string resources + one-shot localized `announcer.announce` on crossing; merge the readout into one node. (Consolidates 03-T4/T5, 02-S3.)

**A7 — Low — guard coverage gap lets A1 recur; one dead resource remains.** `StringResourceUsageTest:444-462` matches only four syntactic literal forms, so parameter-passed and enum/data-held literals are invisible; the strengthened `:471-501` format-arg checker covers all 318 resource call sites but only *resources*. `a11y_formula_editor` (`strings.xml:1261`, `strings_hi_1.xml:19`) is defined in both locales but never referenced — `MathLiveEditor.kt:138` uses only `a11y_formula_editor_value`. *Fix:* extend the guard to data-holder/parameter literals (or a curated allowlist of literal-bearing enums); delete or use the dead resource.

## Re-verified as fixed since 0.0.53

- **Parity complete:** 1,291 EN / 1,271 HI names; all 20 EN-only are exactly the `translatable="false"` set (app_name, mcq_app, 16 `theme_*`, `l_02d_02d`, `l_1f_0f`, `label`); **0** HI-only, **0** placeholder mismatches, **0** plural-quantity issues, **0** unescaped-apostrophe issues, **0** duplicates (guards `:410-437`, commit `14888e0`).
- **Announcement mechanism exists:** `LocalAnnouncer`/`Announcer` (`UiMessage.kt:38-49`), provided at `MainActivity.kt:60-69`; `announceForAccessibility`; `liveRegion = Polite` in `PagingStates.kt:56`, `SearchScreen.kt:134`, `QuestionEditorScreen.kt:180` (db612e0). Old "zero announcements" claim is false today.
- **Option states have a channel:** `Role.Checkbox` + `stateDescription` at `StudyScreen.kt:852-861` (copy defect is A2, not a missing mechanism).
- **Verdict/layout a11y:** `verdictColorsFor` palette-derived from the active scheme, skips neutral, single `isDark` helper (`VerdictColors.kt:32-49,58-76,103-116`); glyph+word pairing; chart `testTag` separated from localized `contentDescription` with per-series summaries (`ChartKit.kt`, `UiAccessibilityTest:113-179`); WebView editor speaks its value.
- **Counts/plurals/stale names/unused resources:** `convertedCountNamesArePluralsWithDistinctForms` (25 names); no `sm_2_*`, `simplified_anki`, `l_0f` remain; unused resources 25 → **1** (A7); `time_taken_02d_02d` binding verified in both locales (`StringResourceUsageTest:510-534`).
- **Language picker & locale plumbing:** Settings → Appearance → Language with SYSTEM/ENGLISH/HINDI, platform per-app locales + pre-33 context wrap (round-2 07 verified; `AppLanguageTest`, `LanguagePreferenceTest`, `LanguagePickerResourcesTest`). No `configChanges`; no double recreate.
- **Feedback copy resource-backed:** 42/42 `final_*` names in both locales; `StringResourceUsageTest:471-501` covers format-arg call sites previously claimed "invisible".

## Checked, no defect

- **RTL:** `supportsRtl="true"` (`AndroidManifest.xml:12`) and all 21 navigational icons use `Icons.AutoMirrored` (back arrows, chevrons, list/menu); Hindi is LTR, so no RTL locale is shipped — no mirrored-icon defect found.
- **Colour-only meaning:** verdicts pair colour with glyph + spoken label (`Verdict.kt:16` `labelRes`), Study marks are distinct shapes, charts use the `chartSeriesColor` contrast guard for all six roles.
- **Escaping/formatting:** no unescaped apostrophes, no raw Kotlin `$template` in resources, no leading/trailing whitespace on translatable strings (guard `:340-353,412-420`).
- **Touch targets (modifier-based):** `UiAccessibilityTest:43-53` passes for all `IconButton`/`IconToggleButton`; no-op `IconButton` guard (`:33-40`) passes.
- **Resource usage:** every `stringResource` renders in a sink; every referenced resource is defined (`:259-337`).

## Owner decisions

1. Approve promoting the ~70 literals (A1) to resources in both locales, or accept selected ones as intentionally English (Anki-style month abbreviations, brand/format names).
2. Choose the formula-content a11y fallback (A4): plain-text `stateDescription` vs full WebView accessibility tree; and the exact verdict announcement copy after Check/reveal (A2/A6).
3. Accept `a11y_formula_editor` deletion (A7), and decide whether to generalize the literal guard now or track as a known blind spot.
