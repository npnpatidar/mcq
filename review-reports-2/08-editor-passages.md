# Round-2 review — Question editor & Passages

**Branch:** `feature/review-round-2` @ `fbc8e15` (= main, release 0.0.61). Read-only; no product/test/docs code changed.
**Scope:** `ui/editor/**` (QuestionEditorScreen, EditorViewModel, EditorSession, BlockListEditor, MathLiveEditor/MathMlLatex), `PassagesScreen`/`PassagesViewModel`, rich-text WebView (`util/ContentElements`, `data/RichTextHtml`), block ids/reorder, identity-addressed writes, save validation, schedule-reset disclosure, dirty guard, rotation/i18n/a11y; cited navigation/data helpers only where a UI claim depends on them.
**Method:** old `review-reports/08`, `09` treated as **claims**; `git log -p 0.0.53..HEAD` on these files read commit by commit (c189b26, 99bcea6, 0b88edd, db612e0, 4574abf, 9455bf1, c68ace5, fdbe8ba). Platform claims checked against official docs, cited inline.

## Verdict

The two High claims are genuinely fixed: formula writes now carry a stable block id, and the cross-paper check re-reads membership at save time. The disclosure, tag, whitespace and localization-of-errors fixes also hold. But four previously reported problems (Cancel losing a passage draft, rotation losing dialogs, `LaunchedEffect(Unit)` disabling Save, pager error as empty state) are still present despite release notes implying closure, and the a11y "fix" replaced hidden WebView content with a generic label that hides the question entirely. The dirty guard is also confined to one composable.

## Findings

**E1 — Medium — Cross-paper "Cancel" still destroys the edited passage form.** `PassagesScreen.kt:552-574`: the edit dialog renders only while `pendingCrossPaperSave == null`; publishing the warning at `:217` removes it from composition, so its plain-`remember` fields (`:631-633`) are destroyed. Cancel (`:611`) clears the warning, and the dialog re-enters seeded from the unchanged `editing` passage — title, body and category edits are gone. `PassagesUiTest.kt:78-98` only asserts that nothing was written, not that the draft survives. *Why missed:* c189b26's comment says staging "lives on the ViewModel … so … lose the user's edit", but that covers the count query/warning, not the form fields. *Fix:* hoist the draft into `PassagesViewModel` keyed by passage id (or keep the dialog mounted and pass the draft inside `pendingCrossPaperSave`).

**E2 — Medium — Rotation still loses every open dialog and typed draft.** `QuestionEditorScreen.kt:120-121` (`showLeaveDialog`, `showDeleteDialog`), `PassagesScreen.kt:330-332` (`editing`, `creating`, `deleteRefusal`) and `:631-633` (title/text/category) all use plain `remember`. The system "calls `onDestroy` … then creates a new instance using `onCreate`", and `remember` — unlike `rememberSaveable` — does not survive that ([runtime changes](https://developer.android.com/guide/topics/resources/runtime-changes), [state restoration](https://developer.android.com/develop/ui/compose/state#restore)). Rotating mid-entry on Passages loses the typed passage outright; rotating the editor's leave dialog dismisses it and leaves unsaved edits one Back tap from being discarded. *Why missed:* old 08 listed "rotation survival via VM/rememberSaveable" as a non-defect, and 09's M11 was triaged Low and never carried forward. *Fix:* `rememberSaveable` for flags/drafts, or VM-owned draft state.

**E3 — High (a11y) — Formula-bearing content is one generic TalkBack node with its text hidden.** `ContentElements.kt:49-51` routes any question containing a `MathElement` into `MixedContentView`, where `:540-542` applies `Modifier.semantics(mergeDescendants = true) { contentDescription = contentLabel }` and `contentLabel` is the constant "Rendered question content with formulas" (`strings.xml:1263`). Merging descendants makes the WebView a single leaf, and the fixed description carries no question text, table cells or math, so a screen-reader user cannot read the question at all (the plain-text path at `:53-56` is not taken). Compose docs: `mergeDescendants = true` "indicates that the semantics properties should be merged" and services present a single node ([semantics](https://developer.android.com/develop/ui/compose/semantics)). *Why missed:* db612e0 answered "WebViews unlabelled" by adding a label, but a label is not the content. *Fix:* expose a real accessible text fallback (plain-text/`stateDescription` or a non-merging labelled node); ideally let TalkBack traverse the WebView's own accessibility tree ([accessible WebView](https://developer.android.com/guide/webapps/accessible-webview)).

**E4 — Medium — Dirty guard is local to one composable; external navigation bypasses it.** `QuestionEditorScreen.kt:122-129` guards only `BackHandler` and the top-bar icon. Any `navController.navigate` from elsewhere pops/replaces the editor with no `isDirty` check; in particular `MainActivity.kt:75,89-100` re-handles the SEND intent on *every* `onCreate`, so rotating a dirty editor while a file was shared navigates to `import/direct` and loses the edits (report 01 L1). *Why missed:* old 08 verified the leave dialog and BackHandler but never asked what happens when navigation originates outside the editor. *Fix:* make the guard VM/NavHost-owned (or at minimum consume the SEND intent once so rotation cannot navigate).

**E5 — Low — `EditorSession` snapshot is still torn and unsignalled.** `EditorSession.kt:42-49` keeps four independent `@Volatile` fields; `:105-120` mutates them off Main, and `QuestionEditorScreen.kt:150-153` reads index/size/prev/next separately during composition. A reanchor can publish a new `size` before the new neighbours, and because reanchor emits no state, the counter/Prev/Next can stay stale until an unrelated state change. `captureTarget` (`:87-97`) then silently refuses a stale neighbour with only a log. Old 08 Medium claim still open. *Fix:* one immutable snapshot object behind a single volatile/StateFlow reference.

**E6 — Low — Pager `LoadState.Error` still renders as "No passages yet".** `PassagesScreen.kt:525-538`: when `itemCount == 0`, only `LoadState.Loading` gets a spinner; every other state (including `LoadState.Error`) falls through to `R.string.passages_empty`, with no retry. Old 09 Low claim still open. *Fix:* branch on `LoadState.Error` with a localized retry row.

**E7 — Low — A new passage can be permanently unsavable.** `PassagesScreen.kt:644-648` seeds `categoryId` in `LaunchedEffect(Unit)`; if the create dialog opens before `state.papers` emits (`PassagesUiState.loading = true`, `PassagesViewModel.kt:160-165`), `categories` is empty and the effect never re-runs, leaving `categoryId` blank and Save disabled forever (`:717`). Old 09 claim still open. *Fix:* derive the fallback at save time or key the effect on `papers.isNotEmpty()`.

**E8 — Low — Difficulty dropdown stays English under Hindi.** `QuestionEditorScreen.kt:914,926` render `Difficulty.label`, hardcoded `"Easy"/"Medium"/"Hard"` in `Models.kt:204-207`; no string resources exist for them. The "complete Hindi translation" pass could not catch data-held literals. *Fix:* add localized resources and resolve with `stringResource` at the call sites, keeping the stored label token unchanged for imports/FKs.

**E9 — Low — Schedule disclosure hashes form content on Main on every keystroke.** `EditorViewModel.kt:197-198` recomputes `editorCardFingerprint` (which calls `CardContent.of` → SHA-256 of all blocks, including large base64 images) whenever the screen recomposes to read `willResetSchedule` at `QuestionEditorScreen.kt:568`. *Fix:* compute once in `updateState`/load and store it in `EditorUiState`.

## Re-verified as fixed since 0.0.53

- **H5 (formula after reorder):** block ids move with elements (`EditorViewModel.kt:839-861,1021-1045`), Compose keys are id-based (`BlockListEditor.kt:85-87,207-208`), and the once-installed bridge carries `blockId` (`MathLiveEditor.kt:117-123,176-186`) resolved against current lists at callback time (`EditorViewModel.kt:336-361`; `MathBlockIdentityTest.kt:46,106,126`).
- **H6 (stale member count):** `PassagesViewModel.decideSave` re-reads `passageMemberCount` at save time (`:183-193`), staged/confirmed/cancelled on VM scope with generations (`:202-284`).
- **Schedule-reset disclosure:** `willResetSchedule` uses the same `CardContent` side as `saveQuestion` (`EditorViewModel.kt:190-198,450-466`; `QuestionStore.kt:281-289`) and an inline note renders at `QuestionEditorScreen.kt:565-574`.
- **Half-typed tag:** `rememberSaveable(state.questionId)` resets the draft on Prev/Next but keeps it on rotation (`QuestionEditorScreen.kt:454`).
- **Whitespace no-op:** trim-vs-trim comparison keeps rich elements (`PassagesScreen.kt:692-703`).
- **Errors localized:** `friendly()` replaces all editor literals (`EditorViewModel.kt:499-501`, fdbe8ba).
- **WebView hygiene:** both WebViews set `allowFileAccess/contentAccess = false`, refuse navigation and tear down via `onRelease` (`MathLiveEditor.kt:150-167,212-219`; `ContentElements.kt:480-503,527-533`); `setAllowFileAccess(false)` disables file-system access only — "Assets and resources are still accessible using file:///android_asset" ([WebSettings](https://developer.android.com/reference/android/webkit/WebSettings#setAllowFileAccess(boolean))).

## Checked, no defect

- Preview HTML escaping: `renderInlineHtml` re-emits an allow-list with attributes dropped, `stripMathAttributes` sanitizes MathML and escapes unknown tags, image `src` is attribute-escaped, no CSP bypass via injected values (`RichTextHtml.kt:15-47,81-105,107-123`; `ContentElements.kt:187-303`).
- MathLive bridge posts callbacks back to the view's main thread (`MathLiveEditor.kt:179-185`), matching the documented "private, background thread" of injected objects ([WebView.addJavascriptInterface](https://developer.android.com/reference/android/webkit/WebView#addJavascriptInterface(java.lang.Object,%20java.lang.String))). The HTML has no CSP, but `initialJson` is caller-quoted; unit tests feed pre-quoted strings, so pin the hostile-`</script>` case if this is ever changed.
- `blockIds`/elements stay parallel for add/remove/move/table/image/math writes; `idsMoved`'s remove-then-insert yields the intended order.
- `editorSnapshot` is length-prefixed (no delimiter collisions, whitespace preserved); marks/tags normalization matches `buildDto()` (`EditorViewModel.kt:378-426,1158-1177`).
- Passage pick is guarded by sequence, question/paper identity and current category, and a stale cross-paper pick is ignored (`EditorViewModel.kt:776-815`).
- Import draft fail-closed, delete refuses import previews, delete targets the current `questionId`, save/Prev/Next gated on one operation and on keystrokes during a write (`EditorViewModel.kt:1202-1213,1296-1328,1403-1416,1539-1554`).
- Tag dedupe/fold and option-id minting after a middle removal are correct (`EditorViewModel.kt:726-748,943-961`); `newTag` no longer follows the user across questions.
- Image encoding runs on IO and writes by stable id (`EditorViewModel.kt:1513-1532`); Room suspend reads do not block Main.

## Owner decisions

1. E1/E2: accept VM-owned passage/editor drafts (and `rememberSaveable` dialog flags) as the contract, or keep the current "cancel resets the form" behaviour and document it.
2. E3: choose the accessible representation for formula content (plain-text fallback vs WebView traversal) — it affects Study, Browse and the editor preview, not just this screen.
3. E4: whether to make the dirty guard global; this is coupled to report 01 L1 (SEND replay on every `onCreate`).
4. E8: introduce difficulty string resources (storage label must stay a stable token).
5. Collision copy (`strings.xml:61`) still omits the case where the destination card wins and source history is dropped.
