## Verdict

Most of the earlier medium findings are genuinely fixed: TESTS now says "All time", the failed card sheet stays mounted with Retry, charts carry real screen-reader summaries, errors have a retry button, epoch disclosure exists, and day bucketing is calendar/DST-based. Two new/remaining issues are worth a fix: the calibration BCa interval does **not** resample its stated cluster unit (contradicting its own comment), and chart/date labels stay English in the Hindi locale. Several low-severity leftovers remain. No wrong-paper caching, wrong aggregate, or 04:00 DST error found.

## Findings

**ST1 — Medium — "Card-clustered" BCa bootstrap resamples Easy and Good independently, so it does not preserve the dependence it claims to.** `Calibration.kt:710-714` says "both classes are resampled together so their covariance is preserved"; `:742-748` draws `a = resampleMean(cardsFirst, random)` and `b = resampleMean(cardsGood, random)` as two **independent** multinomial draws, and `:818-832` deletes a card that appears in both classes from only `first` (for `good` the skip index is `first.size + i`, so a shared card removed from `first` stays in `good`). A card routinely contributes residuals to both grade classes (Easy at one review, Good at another), so the resampling unit is neither the card nor paired. SciPy's API states the distinction explicitly: `paired=True` "resamples an array of indices and uses the same indices for all arrays … otherwise, bootstrap independently resamples the elements of each array" ([scipy.stats.bootstrap](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.bootstrap.html)); the cluster-bootstrap literature requires resampling clusters while "preserv[ing] correlation within clusters" ([Cameron, Gelbach & Miller](https://www.nber.org/system/files/working_papers/t0344/t0344.pdf)). Effect: the 90% interval driving `readiness.precisionMet`, `contrast.direction`, `MAX_HALF_WIDTH` and the cut suggestion is an independence-model interval, and its jackknife acceleration is computed under a different deletion scheme than its bootstrap. *Why missed:* the earlier audit never opened `contrast()`; the confident comment reads as proof. *Fix:* build the union of cards, draw one card-index sample per replicate, recompute both class means from the drawn cards (paired cluster bootstrap), and delete a shared card from both classes in `acceleration()`.

**ST2 — Medium — Chart dates and axis labels are hard-coded English despite the complete Hindi locale.** `StatsAggregator.kt:1331` (`"d MMM"`, `Locale.ENGLISH`), `:1871` (`"MMM yy"`), `:2593-2594` (both chart formats), `:1905-1914` (`STABILITY_LABELS`/`INTERVAL_LABELS` literals), `HeatmapChart.kt:61-62`, `CardInfoSheet.kt:44` (`"d MMM yy, HH:mm"`, `Locale.ENGLISH`). A Hindi user sees translated headings and error copy but English month names and labels such as "2–4m", "0–5s", "1–2w". PROJECT_NOTES requires all user-facing copy to resolve with the selected locale. Number formatting via `Locale.ENGLISH` elsewhere (e.g. `ChartKit.kt:294`) is deliberate and is **not** part of this finding. *Why missed:* locale tests cover string resources; these are literals/formatters in domain and Canvas code. *Fix:* resolve labels with `stringResource` at the render site (or pass a formatter/locale into `Input`), and use the selected locale in `DateTimeFormatter`.

**ST3 — Low — Stability histogram bins are labelled as time intervals.** `StatsAggregator.kt:1905-1909` renders stability bins as `"<1d"`, `"1–3d"`, `"1–2w"`, `"6m–1y"`. Upstream is explicit that in FSRS-7 "Neither value directly means the time for R to drop to 90%" ([ts-fsrs FSRS-7](https://open-spaced-repetition.github.io/ts-fsrs/guide/model/fsrs-7.md)); PROJECT_NOTES also forbids rendering `S` with a `d` suffix. The card sheet correctly shows unitless `S` (`CardInfoSheet.kt:88-94`), so the same number is unitless in one place and a duration in another. *Why missed:* earlier audit logged it as Low copy and no fix batch took it. *Fix:* unitless bin names plus a caption; owner decision on wording.

**ST4 — Low — Welch-tier interval uses a fixed critical value that under-covers near its floor.** `Calibration.kt:811-814` uses `t = 1.70` for `20 ≤ bindingCards < 40`, claiming it is conservative. The exact two-sided 90% critical value at df=19 is ≈1.729, so at the low end of the tier the interval is slightly too narrow (precision gating is slightly too optimistic). *Fix:* compute the t quantile from the Welch–Satterthwaite df, or use a lookup ≥1.729 at the floor.

**ST5 — Low — Unknown grade in the card sheet still renders as Easy.** `CardInfoSheet.kt:176-181`: `else -> grade_easy`. Ratings outside 1–4 (corrupt/hand-edited rows) are shown as a confident Easy; `FsrsReplay.kt:281-285` and `WorkloadAccumulator` deliberately fold such rows into Good/skip them instead. *Fix:* render "—" for out-of-range ratings.

**ST6 — Low — Remaining chart a11y/font-scale gaps.** `ChartKit.kt:148-154,169-187` and `StackedBarChart.kt:62-73` speak only each bar's total, not its named segments, so a stacked chart's series cannot be distinguished by screen reader; `LineChart.kt:84,101,171` and `StackedBarChart.kt:102,129` keep a fixed `200.dp` canvas and `9.sp` labels, which can clip a scaled axis. The old "test tag as contentDescription" bug is fixed; this is the residual. *Fix:* add per-segment points to `chartSummary` and derive chart height from font scale.
