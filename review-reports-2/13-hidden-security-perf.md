# Round-2 review — hidden behaviour, security, performance, error handling

**Branch:** `feature/review-round-2` @ `fbc8e15` (= main, release 0.0.61). Independent read-only reviewer; no product code, tests, gradle or commit touched.
**Scope:** first-run defaults, schedule-reset-on-edit, "enable new cards", per-paper vs whole-bank progress, Anki FSRS disclosure; manifest/exported components, SEND intents, FileProvider/SAF, WebView JS bridges, zip/HTML sanitisation; logging of personal data, temp-file/permission hygiene; main-thread I/O, large-data memory, coroutine scopes, double-tap/crash windows.
**Method:** old `review-reports/{00-baseline,16-d-data-integrity,18-f-hidden-behaviour}.md` treated as **claims** and re-derived from current source. Platform claims checked against official docs: [Auto Backup](https://developer.android.com/guide/topics/data/autobackup), [DataStore backup](https://developer.android.com/topic/libraries/architecture/datastore#device-backup-and-restore), [WebSettings.setAllowFileAccess](https://developer.android.com/reference/android/webkit/WebSettings#setAllowFileAccess(boolean)), [AOSP `JSONObject.quote` → `JSONStringer.string`](https://android.googlesource.com/platform/libcore/+/refs/heads/master/json/src/main/java/org/json/JSONStringer.java), [StrictMode](https://developer.android.com/reference/android/os/StrictMode), [OWASP Logging Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Logging_Cheat_Sheet.html).

## Verdict

No exploitable security defect and no High/Critical issue. The WebView, SAF and zip surfaces are genuinely hardened; the 0.0.54–0.0.61 disclosure batch fixed the first-run hint, the editor schedule-reset note and the Anki-memory notice. Four real but Low/Medium items remain: one definite backup-rules misconfiguration, two undisclosed hidden behaviours carried over from the old audit, and one privacy consideration in the optional log export. Several other "claims" are confirmed fixed or are explicit owner trade-offs.

## Findings

**H1 — Medium — Backup rules exclude every real setting and back up only a transient import journal.** `res/xml/data_extraction_rules.xml:14-27` and `backup_rules.xml:4-9` use `<exclude domain="file" />` + `<include domain="sharedpref" />`, with the comment (`:10-11`) claiming "font scale, scheduler config … kept so a restored device looks familiar." But the app's entire settings store is Preferences DataStore (`RepositorySettings.kt:35` `preferencesDataStore(name = "settings")`), which lives under `files/datastore/` — the **`file`** domain, explicitly excluded. Official docs: "Preferences DataStore files (`*.preferences_pb`) … are stored in the app's `files/datastore/` directory. By default, these files are included in Android Auto Backup" and the backup rules must `<include domain="file" path="datastore/…"/>` ([DataStore backup](https://developer.android.com/topic/libraries/architecture/datastore#device-backup-and-restore); [`file` = `getFilesDir()`](https://developer.android.com/guide/topics/data/autobackup)). The only `sharedpref` file the app writes is `import_run.xml`, holding the last import's paper title or `content://…` source key (`ImportRunJournal.kt:32-41,63`; `ImportViewModel.kt:1011,1015`). Net effect: cloud/D2D restore carries a stale "previous import stopped" hint and loses theme, language, FSRS weights and every scheduler setting, contrary to the comment. *Why missed:* previous reviews audited backup *content/wipe* integrity, never the XML domain mapping; the misleading comment reads like a correct design note. *Fix shape:* add `<include domain="file" path="datastore/settings.preferences_pb"/>` to both sections (and exclude only the install-freshness marker if desired), or delete the comment and document that no settings survive cloud restore. Owner call: is keeping settings in cloud backup even wanted, given content is deliberately excluded?

**H2 — Low — Per-paper JSON (and ZIP) export silently drops card schedules.** `PaperExporter.kt:138-140` renders `JSON_INLINE` via `PaperJsonWriter.writePaperJson`; `PaperJsonWriter.kt:37` writes a `{"version":1,"papers":[{…}]}` envelope, and `PaperDto` (`JsonDto.kt:102-111`) has no `scheduling` field. `loadScheduling()` (`PaperExporter.kt:115-120`) is passed only to the APKG writer (`:164-166`); every other format gets the empty default (`:133`). The picker description `"… data URIs. Re-importable."` (`ExportFormat.kt:11-16`) says nothing about progress, while the whole-bank help explicitly promises schedules (`strings.xml:110`), so a learner who exports one paper and re-imports it loses all intervals with no warning. This is old F5, untouched by the disclosure batch. *Why missed:* the round-2 import/export reviews checked whole-bank v2 scheduling and the alias keys, not the per-paper DTO. *Fix shape:* extend the per-paper envelope with `scheduling` under a bumped version and reuse `CardScheduleMapping.lookupCardSchedule`, or state "content only — study progress is not included" in the format description (and Hindi counterpart).

**H3 — Low — The empty-state "Introduce new cards" button is a global switch, but is presented per paper.** `StudyViewModel.kt:1377-1398` reads the stored config and writes `introduceNewCards = true` to the global `introduceNewCardsKey` (`RepositorySettings.kt:352,520`), then repulls the current paper only. The button at `StudyScreen.kt:1040-1051` sits in a paper-specific empty session and is labelled just "Introduce new cards" (`strings.xml:652`). Turning it on silently enables new cards in every other paper; a learner who studies paper A cannot tell that paper B's review-only setting changed. Old F3, not addressed by `9455bf1`. *Why missed:* the disclosure batch enumerated first-run grading, editor reset, Anki memory and calibration, but not this control. *Fix shape:* relabel to "Introduce new cards in all papers" (with Hindi copy), or make the toggle study-scoped.

**H4 — Low — Optional "Export Logs" shares user titles and raw exception text without warning.** `BackupDataSection.kt:117-136` shares `Logger.logFilePath()` via FileProvider + `ACTION_SEND`. The log contains user-authored paper/category titles (`PaperExporter.kt:51,63,79`; `PaperStore.kt:140,230,458`; `QuestionStore.kt:261-263`), full throwable stack traces (`Logger.kt:103-123,155-174`, e.g. `Logger.e(..., e)` on every failure path) and occasional content URIs. FileProvider rules (`file_paths.xml:3-4`) expose both log dirs; the file is 8 MB-capped and excluded from cloud backup (good). OWASP advises that logs must not contain sensitive data and that debug/log output be minimised ([Logging Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Logging_Cheat_Sheet.html)). Impact is self-disclosure only — the user deliberately shares the file and other apps cannot read the app-specific dir — but a diagnostic share can leak exam names or file paths to a third party. *Why missed:* logging hygiene was reviewed for crash durability, never for what the export button publishes. *Fix shape:* add a one-line "logs may include your paper names" note to the export dialog (2 strings), or redact titles at the `Logger` call sites.

## Checked, no defect

- **Manifest / intents:** only `MainActivity` is exported (launcher + SEND); no deep links, no exported services/receivers. FileProvider is `exported=false`, `grantUriPermissions=true` (`AndroidManifest.xml:16-42`). This report does not re-litigate the SEND-replay-on-rotation bug already filed as L1 in report 01.
- **SAF/URI handling:** `copySendToCache` bounds the stream to 64 MB, sanitises the display name and deletes partials (`SharedImport.kt:91-140`); exports render to a unique temp file and copy only after success, deleting in `finally` (`ShareExport.kt:154-200`); old shares are swept (`ShareExport.kt:47-78`); Anki temp files are swept at startup (`AnkiTempFiles.kt:24-47`).
- **WebViews:** both disable file/content access, override all navigation and remove the bridge + `destroy()` on release (`ContentElements.kt:480-533`, `MathLiveEditor.kt:149-219`). `setAllowFileAccess(false)` blocks the filesystem but not bundled `file:///android_asset` scripts ([WebSettings](https://developer.android.com/reference/android/webkit/WebSettings#setAllowFileAccess(boolean))), so MathJax/MathLive still load as intended. Rich content is sanitised by tag allow-lists that drop every attribute (`RichTextHtml.kt:15-47,81-105`), and the preview page pins `img-src data:`. The MathLive page has no CSP, but its only interop input is `JSONObject.quote(initialLatex)` (`MathLiveEditor.kt:127`), and AOSP's `quote` escapes `/` via `JSONStringer.string`, so a `</script>` payload cannot break out of the inline script ([AOSP source](https://android.googlesource.com/platform/libcore/+/refs/heads/master/json/src/main/java/org/json/JSONStringer.java)). The bridge itself only writes a MathML string. No XSS found.
- **Zip/HTML:** `SafeZip` caps entries, per-entry and total decompressed bytes from actual reads (`SafeZip.kt:23-146`); backups and Anki packages are parsed in memory or streamed, never extracted to attacker-named paths, so zip-slip does not apply.
- **ANR / memory / scopes:** import picks and image decode run under `withContext(IO/Default)` (`LibraryViewModel.kt:141-196`; `EditorViewModel.kt:1517-1519`); Room/DataStore are suspend APIs; the pre-33 DataStore read in `attachBaseContext` is already filed as SE6 (report 07). `ContentHeightCache` is a 32-entry LRU; `sessionScope` jobs are short-lived writes with CAS guards. Grade taps are claimed before launch (`StudyViewModel.kt:1127-1132`), so no double review. (The mid-grade `restart()` race is filed as S1 in report 02; the streaming-backup schedule memory growth as I3 in report 09.)

## Owner decisions / accepted known trade-offs

1. **H1:** include `files/datastore/` in cloud/D2D backup, or accept that no settings survive and correct the XML comment.
2. **H2:** add schedules to the per-paper envelope (format change + version bump) or disclose "content only" in the picker.
3. **H3:** global wording vs. per-paper scope for the empty-state toggle.
4. **H4:** warning on log export vs. redacting titles in log lines.
5. Accepted trade-offs left alone: content excluded from cloud backup; large import as one Room transaction; DataStore+Room commit gap on restore; advisory release-notes check; Anki deck FSRS state re-derived via the SM-2 bridge.
